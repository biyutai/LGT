# Scaling Demo Card

`01_landscape_1280x960.bmp` is a 24-bit, uncompressed, bottom-up BMP cropped
from the official `lab_ex5_i2s/doc/convert/1.png` example image with
`scripts/make_large_bmp.py`. The FPGA reduces it to 640x480 by selecting every
other source pixel and row.

`02_forest_320x180.bmp` comes from the official
`lab_ex5_i2s/doc/convert/3.png` source is now staged as `02_forest_640x480.bmp`
(`scripts/make_large_bmp.py --size 640x480`), and the strawberry is staged as
`03_strawberry_1024x768.bmp`, which the FPGA decimates 8:5 down to 640x480
(`bmp_read` 的 1024x768 通路，见 `doc/系统架构与数据通路.md` 第 13 节).

演示卡配图规则（官方要求源分辨率 ≥ 640×480，且演示要覆盖不同档）：

| 文件 | 源分辨率 | FPGA 通路 |
|---|---|---|
| `01_landscape_1280x960.bmp` | 1280×960 | 2 抽 1 降到 640×480 |
| `03_strawberry_1024x768.bmp` | 1024×768 | 8 抽 5 降到 640×480 |
| `02_forest_640x480.bmp` | 640×480 | 原样透传 |
| `04_apple_640x480.bmp` | 640×480 | 原样透传 |

即"两张正好 640×480、两张高于 640×480 且互为不同分辨率"。根目录**首张放 640×480** 可以让
"看见第一帧"从 1.2~2.5s 压到 0.3~0.6s（首图加载时间 = 文件大小 / 读卡速度）。板子按 FAT32
根目录项顺序扫描，按显示顺序拷贝文件即可保证轮播顺序可预期；物理连续不是必要条件。

`05_demo_beat.wav` is a 12-second 48 kHz stereo PCM demo: the original chord
progression with a soft low-frequency drum hit every 0.5 second. The former
4.3 kHz hi-hat pulse was removed because it sounded like a periodic beep. Use it as
the fifth file to show all four bars and the 120 BPM LED pulse. The previous
`05_demo.wav` is a smooth chord demo with only four pronounced onsets, so it
does not make the LED rhythm obvious.

`06_demo_melody.wav` is a second, clearly different track so that the KEY1
long-press "next music" function has something to switch to: 14.5 seconds of
Beethoven's *Ode to Joy* theme (public domain) with bass, a soft pad and a
gentle drum on beats 1 and 3, generated by
`scripts/gen_demo_melody.py`. It is 48 kHz / 16-bit / stereo with the same
44-byte header, ends on a 256-sample boundary and fades in/out over 20 ms, so
the SDRAM loop is glitch-free. Length is deliberately below the 714,752-word
(14.89 s) audio window used by the four-resident-image mode, otherwise the FPGA
would truncate it. Copy both WAVs into the card's root directory: the player
loads the first WAV of the directory at boot and KEY1 long-press steps to the
next one (`fat32_virtual_disk` remembers up to four).

`PLAYLIST.TXT` and `TEXT.TXT` are the two optional configuration files for the
"digital signage" mode (see `docs/superpowers/specs/2026-10-14-product-polish-plan.md`):

- `PLAYLIST.TXT` turns the slideshow into an operable programme list — one line per
  entry: `index, seconds, transition, subtitle text`. `seconds = 0` means "follow the
  audio beat"; an empty field falls back to the default; unknown transitions fall back
  to fade. Without the file the player keeps its original behaviour (directory order,
  beat-driven switching), so a demo card can never break because of a missing config.
- `TEXT.TXT` is the fallback scrolling subtitle when no playlist is present (one line
  per message, cycled in order). With neither file the bottom line stays the original
  technical ticker.

The current five-file demo set is staged at `%TEMP%\FPGA_stretch_card_20261005`:
1280x960, 320x180, 320x240, 640x480, then WAV. The previous card contents
are backed up at `%TEMP%\FPGA_scale_card_backup_before_stretch_20261005` and
were SHA-256 compared with the removable `FPGA` card before rewriting it.
